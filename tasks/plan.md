# План реалізації: Cloud Media Converter & Archiver

## 1. Загальний огляд
Розробка розподіленого веб-застосунку для обробки ресурсомістких задач (конвертація медіа, важка архівація) із балансуванням навантаження на базі Nginx, асинхронною чергою воркерів на Redis, відстеженням прогресу в реальному часі та адмін-панеллю моніторингу.

---

## 2. Ключові архітектурні рішення
1. **Розділення API та Воркерів:** HTTP-запити від клієнтів не блокують бекенд — вони ставляться у чергу Redis. Обчислення виконуються в пулі ізольованих воркерів.
2. **Балансування навантаження:** Мінімум 2 екземпляри веб-серверів за Nginx Load Balancer (вимога №5).
3. **Спільне сховище (Shared Volume):** Єдиний Docker volume монтується до API-серверів та воркерів для доступу до вхідних і вихідних файлів.
4. **Стрімінг прогресу:** Використання SSE (Server-Sent Events) або WebSocket для миттєвого відображення відсотка та етапу виконання (вимога №2).
5. **Контейнеризація:** Запуск усієї інфраструктури (LB, 2x API, Redis, DB, 2x Workers) через Docker Compose однією командою.

---

## 3. Фази реалізації

### Фаза 1: Інфраструктура та Базовий API (Foundation)
- **Завдання 1.1:** Створення Docker Compose структури (Nginx + 2 API сервери + Redis + PostgreSQL/SQLite).
- **Завдання 1.2:** Базова модель даних (Користувачі, Задачі, Статуси) та авторизація (JWT, HTTPS).
- **Завдання 1.3:** Налаштування балансування в Nginx (upstream з двома бекендами) та перевірка працездатності балансувальника.
*Чекпойнт 1: Nginx успішно розподіляє запити між двома API-серверами, працює автентифікація.*

### Фаза 2: Обчислювальні воркери та Черга задач (Core Engine)
- **Завдання 2.1:** Реалізація черги завдань (Redis + Воркери).
- **Завдання 2.2:** Модуль задач: стиснення (ZIP, 7Z, TAR.GZ) та конвертація зображень/медіа.
- **Завдання 2.3:** Механізм публікації прогресу (відсоток, поточний стан) та скасування задачі.
- **Завдання 2.4:** Валідація лімітів трудомісткості (розмір файлу, таймаут, ліміт активних задач).
*Чекпойнт 2: Задачі успішно обробляються пулом воркерів, прогрес коректно оновлюється, працює скасування.*

### Фаза 3: Інтерфейс користувача (Frontend UI)
- **Завдання 3.1:** Головна сторінка: форма створення задачі (вибір формату, Drag & Drop файлу або генератор синтетичних даних, клієнтська валідація лімітів).
- **Завдання 3.2:** Інтерактивний монітор поточної задачі (прогрес-бар, кнопка скасування, попередній перегляд результату).
- **Завдання 3.3:** Сторінка історії задач та скачування готових результатів.
*Чекпойнт 3: Користувач може авторизуватись, запустити задачу, спостерігати за живим прогресом і завантажити результат.*

### Фаза 4: Бонусний функціонал (Bonus Points)
- **Завдання 4.1:** Черга очікування при вичерпанні ресурсів з розрахунком приблизного часу (ETA) (бонус №6).
- **Завдання 4.2:** Автоматичне горизонтальне масштабування воркерів при зростанні черги (бонус №7).
- **Завдання 4.3:** Панель адміністратора: моніторинг воркерів, CPU/RAM та активних задач (бонус №8).
*Чекпойнт 4: Усі додаткові вимоги реалізовані та протестовані.*

## 4. Ризики та їх мінімізація

| Ризик | Вплив | Стратегія вирішення |
| :--- | :--- | :--- |
| Повільне завантаження важких файлів під час демонстрації | Високий | Генератор синтетичних файлів заданого розміру прямо на сервері (демо в 1 клік) |
| Зависання важких процесів конвертації | Середній | Жорсткий `timeout` на рівні воркера (Process Kill) із записом статусу `FAILED_TIMEOUT` |
| Складність налаштування Docker на різних ОС | Середній | Чіткий `docker-compose.yml` з фіксованими образами та `Dockerfile` |
